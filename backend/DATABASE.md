# Database Documentation

## Overview

SentinelOS uses PostgreSQL as the primary database with SQLAlchemy as the ORM (Object-Relational Mapping) layer.

## Schema

### Users Table
- `id` (UUID): Primary key
- `email` (String): Unique email address
- `api_key` (String): Unique API key for authentication
- `is_active` (Boolean): Account status
- `created_at`, `updated_at` (DateTime): Timestamps

### Repositories Table
- `id` (UUID): Primary key
- `user_id` (UUID): Foreign key to users
- `name` (String): Repository name
- `url` (String): Repository URL
- `description` (Text): Repository description
- `is_active` (Boolean): Active status
- `created_at`, `updated_at` (DateTime): Timestamps

**Index**: Unique constraint on (user_id, name)

### Scans Table
Represents vulnerability scan executions.

- `id` (UUID): Primary key
- `user_id` (UUID): Foreign key to users
- `repository_id` (UUID): Foreign key to repositories
- `status` (Enum): QUEUED, RUNNING, COMPLETED, FAILED, CANCELLED
- `progress` (Integer): 0-100 progress percentage
- `total_files` (Integer): Total files in repository
- `files_scanned` (Integer): Files processed
- `started_at`, `completed_at` (DateTime): Execution times
- `error_message` (Text): Error details if failed
- `metadata` (JSON): Custom metadata
- `created_at`, `updated_at` (DateTime): Timestamps

**Index**: status for filtering

### Findings Table
Represents discovered vulnerabilities.

- `id` (UUID): Primary key
- `scan_id` (UUID): Foreign key to scans
- `vulnerability_type` (String): Vulnerability classification
- `severity` (String): critical, high, medium, low, info
- `file_path` (String): Location of vulnerable code
- `line_number` (Integer): Line number
- `column_number` (Integer): Column number
- `cwe_id` (String): CWE identifier (e.g., CWE-89)
- `cwe_name` (String): CWE name
- `owasp_category` (String): OWASP Top 10 category
- `exploitability_score` (Float): 0-10 exploitability score
- `code_snippet` (Text): Vulnerable code excerpt
- `description` (Text): Vulnerability description
- `recommendation` (Text): How to fix
- `is_ignored` (Boolean): False positive flag
- `ignore_reason` (Text): Why it's ignored
- `detection_source` (String): bandit, semgrep, custom
- `confidence` (Float): 0-1 detection confidence
- `metadata` (JSON): Tool-specific data
- `created_at`, `updated_at` (DateTime): Timestamps

### Attacks Table
Represents simulated attack scenarios.

- `id` (UUID): Primary key
- `scan_id` (UUID): Foreign key to scans
- `finding_id` (UUID): Optional foreign key to findings
- `attack_type` (String): RCE, SQLi, XSS, etc.
- `attack_vector` (String): Attack method
- `success_probability` (Float): 0-1 probability
- `impact_score` (Float): 0-10 impact severity
- `mitre_technique` (String): MITRE ATT&CK ID (T1059)
- `mitre_tactic` (String): MITRE tactic (Execution)
- `attack_path` (JSON): Steps to exploit vulnerability
- `impact_description` (Text): Potential impact
- `prerequisites` (JSON): Conditions required for attack
- `mitigation` (Text): How to prevent attack
- `metadata` (JSON): Additional data
- `created_at`, `updated_at` (DateTime): Timestamps

### Patches Table
Represents code fixes/remediation.

- `id` (UUID): Primary key
- `scan_id` (UUID): Foreign key to scans
- `finding_id` (UUID): Optional foreign key to findings
- `original_code` (Text): Vulnerable code
- `patched_code` (Text): Fixed code
- `explanation` (Text): Why this fixes the issue
- `additional_context` (Text): Extra context/resources
- `is_ai_generated` (Boolean): Generated by LLM
- `confidence` (Float): 0-1 confidence in patch
- `can_auto_apply` (Boolean): Safe to auto-apply
- `apply_complexity` (String): simple, moderate, complex
- `applied` (Boolean): Patch applied status
- `applied_at` (DateTime): When patch was applied
- `metadata` (JSON): Additional data
- `created_at`, `updated_at` (DateTime): Timestamps

### Reports Table
Represents final scan reports.

- `id` (UUID): Primary key
- `scan_id` (UUID): Foreign key to scans
- `title` (String): Report title
- `summary` (Text): Executive summary
- `overall_risk_score` (Float): 0-100 risk score
- `critical_count`, `high_count`, `medium_count`, `low_count` (Integer): Finding counts
- `patch_coverage` (Float): % of findings patched
- `remediation_effort` (String): low, medium, high
- `estimated_remediation_time` (Integer): Hours to remediate
- `pdf_url` (String): URL to PDF export
- `json_data` (JSON): Full report as JSON
- `executive_summary` (Text): Executive overview
- `detailed_findings` (JSON): Detailed finding list
- `recommendations` (JSON): Remediation recommendations
- `created_at`, `updated_at` (DateTime): Timestamps

### Agent_Logs Table
Represents agent execution logs.

- `id` (UUID): Primary key
- `scan_id` (UUID): Foreign key to scans
- `agent_name` (String): scanner, threat, attack, patch, report
- `agent_step` (Integer): Agent step number
- `log_level` (String): DEBUG, INFO, WARN, ERROR
- `message` (Text): Log message
- `details` (JSON): Structured log data
- `execution_time_ms` (Integer): Execution time in milliseconds
- `timestamp` (DateTime): When logged

## Setup Instructions

### Using Docker Compose (Recommended)

```bash
docker-compose up postgres
# Database runs on localhost:5432
```

### Manual Setup

#### 1. Install PostgreSQL
```bash
# macOS
brew install postgresql

# Linux
sudo apt-get install postgresql postgresql-contrib

# Windows
# Download from https://www.postgresql.org/download/windows/
```

#### 2. Create Database
```bash
createdb -U postgres sentinelos
```

#### 3. Initialize Schema
```bash
python init_db.py
```

This will:
- Create all tables
- Set up indexes
- Establish relationships

#### 4. Verify
```bash
psql -U postgres -d sentinelos
\dt  # List tables
\q   # Quit
```

## Environment Variables

```bash
# .env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/sentinelos
DATABASE_POOL_SIZE=5
DATABASE_MAX_OVERFLOW=10
```

## Usage in Routes

### Get Database Session
```python
from fastapi import Depends
from app.models.database import get_db

async def my_route(db: AsyncSession = Depends(get_db)):
    # Use db for queries
    user = await db.get(User, user_id)
    return user
```

### Query Examples

#### Get Record by ID
```python
from sqlalchemy import select
from app.models import User

query = select(User).where(User.id == user_id)
result = await db.execute(query)
user = result.scalar_one_or_none()
```

#### List with Filter
```python
from sqlalchemy import select, and_
from app.models import Finding

query = select(Finding).where(
    and_(
        Finding.scan_id == scan_id,
        Finding.severity == "critical"
    )
)
result = await db.execute(query)
findings = result.scalars().all()
```

#### Create Record
```python
from app.models import User
from app.utils.helpers import generate_id

user = User(
    id=generate_id(),
    email="test@example.com",
    api_key="abc123"
)
db.add(user)
await db.commit()
```

#### Update Record
```python
user = await db.get(User, user_id)
user.is_active = False
await db.commit()
```

#### Delete Record
```python
user = await db.get(User, user_id)
await db.delete(user)
await db.commit()
```

## Performance Tips

### Connection Pooling
Configured automatically. Adjust in `config.py`:
```python
DATABASE_POOL_SIZE=5  # Number of connections to maintain
DATABASE_MAX_OVERFLOW=10  # Additional connections under load
```

### Indexes
Add indexes for frequently queried columns:
```python
# In model:
status = Column(String(20), index=True)
```

### Relationships
Load related data efficiently:
```python
from sqlalchemy.orm import selectinload

query = select(Scan).options(
    selectinload(Scan.findings)
)
```

### Pagination
Always paginate when listing:
```python
limit = 20
offset = (page - 1) * limit
query = select(Finding).limit(limit).offset(offset)
```

## Troubleshooting

### Connection Error
```
Error: could not connect to server
```

**Solution:**
1. Check PostgreSQL is running: `pg_isready`
2. Check DATABASE_URL in .env
3. Verify database exists: `psql -l`

### Migration Error
```
Error: No such table
```

**Solution:**
```bash
# Recreate schema
python init_db.py
```

### Constraint Error
```
Error: duplicate key value violates unique constraint
```

**Solution:**
- Generate unique IDs: `from app.utils.helpers import generate_id`
- Check for existing records
